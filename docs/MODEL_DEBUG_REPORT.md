# Machine Learning Debug Report: CTC Loss Failure

## Incident Summary
The deployed HTR application was observed returning 0% confidence and garbage text predictions (e.g., when given an image containing the text "My Name is Shiva."). A full architectural audit was conducted across the neural network pipeline (CNN, BiLSTM, CTC layer, Predictor).

## Root Cause Diagnostics
The root cause was isolated to a critical logical bug in how the CTC (Connectionist Temporal Classification) Loss function calculated string sequence lengths during the **Training Phase** in `src/model.py`.

### The Bug
In the custom `CTCLayer` forward pass, the model computed the target sequence length as follows:
```python
label_length = tf.cast(tf.shape(y_true)[1], dtype="int64")
```
- `y_true` represents the ground truth labels provided in batches.
- To fit inside a tensor matrix, all labels in a batch are padded to `Config.MAX_TEXT_LENGTH` (32) using a pad token (usually `-1`).
- `tf.shape(y_true)[1]` evaluates to the static dimension size of the padded tensor, meaning **`label_length` was evaluated as 32 for every single image**, regardless of the true length of the underlying word.

### Mathematical Consequence
When the model tried to align the CNN feature vectors to the text using CTC Loss:
1. The CNN output `input_length` (time steps) was 32.
2. The `label_length` was forced to be 32.
3. The CTC algorithm mathematically requires `time_steps >= label_length` to perform a valid alignment, but ideally `time_steps > 2 * label_length` to account for repeated character blanks.
4. Because the `label_length` was forced to 32, the model tried to predict 32 characters in exactly 32 time steps, consisting mostly of `-1` (padding).
5. The gradients for the model weights became massively misaligned and degraded into noise, resulting in a trained model that outputs random gibberish.

## Implementation Fix
The `CTCLayer` in `src/model.py` was rewritten to dynamically calculate the actual, unpadded text length for each sequence in the batch:
```python
actual_label_lengths = tf.reduce_sum(tf.cast(tf.not_equal(y_true, -1), tf.int32), axis=-1, keepdims=True)
label_length = tf.cast(actual_label_lengths, dtype="int64")
```
Now, if the label is "Shiva", `label_length` accurately evaluates to `5`, giving the CTC algorithm 32 time steps to comfortably align 5 characters.

## Architectural Verification
No other logic inside the neural network required modification.
- **CNN Architecture:** Verified (Correct down-sampling resulting in 32 feature time steps).
- **BiLSTM Architecture:** Verified (Extracts sequence contexts correctly).
- **Vocab Matching:** Verified (Vocabulary size is 80 (79 chars + 1 blank), which perfectly aligns with `dense_output` dimensions).
- **Inference Pipeline:** Verified (Greedy decode correctly handles actual model logits).

## Conclusion
The application code has been patched. However, the `best_htr_model.h5` weights currently residing in `models/` were generated by the faulty CTC loss logic. **The model must be retrained from scratch.** Please refer to `TRAINING_GUIDE.md` for instructions.
